# Valhalla 偏航重规划接入

接入的是**在线 Valhalla 路线服务**，不是手机离线引擎。首次规划、目的地预览和偏航重算统一使用 Valhalla。Apple 地图保留底图显示和地点搜索；ESP32 仍只接收导航指示。本次不增加道路偏好开关。

## 配置

服务地址统一在 `lib/config/api_config.dart` 的 `ApiConfig.valhallaBaseUrl`：
`https://nav.williamligallery.uk`。`/route` 和 `/status` 均由此派生，使用 HTTPS 443。
旧 `VALHALLA_ROUTE_URL` 构建参数不再生效，避免旧 Xcode 配置覆盖新地址。

重新构建 App：

```sh
flutter run
```

发行构建使用同一源码配置：

```sh
flutter build ipa
```

已安装的旧 App 需要重新构建安装。云端合成坐标联调测试（显式启用）：
`flutter test --dart-define=VALHALLA_CLOUD_TEST=true test/valhalla_cloud_service_test.dart`。

- 所有构建仅允许有效证书的 **HTTPS 443**，不再保留本地 HTTP 例外。
- 不要把管理员密钥或服务端密钥塞进 URL／`--dart-define`：该值会随客户端发布，**不是秘密存储**。商业部署应在服务端实现适合移动客户端的鉴权、限流和配额保护。

## 服务需要提供什么

服务端必须准备覆盖澳洲实际销售、测试区域的 Valhalla **routing tiles（可算路的道路网络）**，包含适用的通行方向、转向限制等数据。地图图片、Apple 底图缓存或原始文件下载本身不能替代可用的算路数据。部署方还需要维护数据更新、服务可用性、容量、日志与隐私策略。

接口返回路线几何和分步指示；Valhalla 不负责这个 App 的全部实时导航状态管理。移动航向通过 `heading`／`heading_tolerance` 帮助引擎选择起步方向，但这是方向约束能力，**不构成全程绝不掉头、车道级定位或正确路线的保证**。低速、失真航向、路网缺失、实际封路等仍须测试和处理。[Valhalla 官方路线接口](https://valhalla.github.io/valhalla/api/route/api-reference/)

不要将公共 demo 当作免费、无限额、具有可用性承诺的生产后端。使用前核对具体运营方的授权、限额、隐私和费用；开源引擎许可不等于托管服务许可。[Valhalla 官方项目与许可](https://github.com/valhalla/valhalla)

## 隐私和地图许可

偏航请求会向配置的服务发送**精确当前位置、目的地，以及可用的移动航向等路线参数**。正式发布前，隐私政策和商店隐私披露应与实际发送、存储、日志保留及第三方处理方式一致。使用合成坐标完成接口联调后，再由测试者知情同意进行实路验证。

OSM 路网数据的归属标注、ODbL 条件与 Valhalla 软件许可分别处理。Apple 地图显示、地点搜索及其他地图供应商也各有使用条件；不能因为采用开源算路引擎就省略底图授权或标注。[OpenStreetMap 版权与许可](https://www.openstreetmap.org/copyright)

## 接入验收

先用合成位置／已获授权的测试轨迹，在安全环境验证：

1. 预览、首次规划及偏航重算均调用同一云端 Valhalla，不退回 Apple。隐私披露须覆盖所有算路请求。
2. 同一坐标、不同有效移动航向，检查返回路线的实际起步方向，不只看第一个转向图标。
3. 错过左转继续前进、对向道路、平行辅路、环岛：新路线应能从最新位置合理接入，不能直接套用旧起点的备用路线。
4. 请求期间继续移动：返回后使用最新位置校验，避免再次提示已经在身后的路口。
5. 静止、航向无效、定位跳点、断网、超时、服务错误、无覆盖数据：不能伪造直行路线或把失效旧指示当成可靠新指示。
6. 接管后检查手机路线、步骤、距离和 ESP32 指示是否一致；再次偏航、暂停／结束导航时，旧请求不能覆盖新状态。

云端接口联调不代表澳洲全境覆盖、并发容量或实路导航效果已经验证。
本次迁移保留原有请求参数（包括原本的 `costing: auto`），不修改服务器端配置。
